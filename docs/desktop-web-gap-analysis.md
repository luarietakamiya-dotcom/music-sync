# Desktop / Web 機能差の確認

確認日: 2026-09-29。Web の比較対象は v0.7.2。

その後の v0.8.0 で、原音・暖かい・クリア・ボーカル・低音・AMラジオ・古いレコード・カセット・電話・隣の部屋の10種類と3段階の強さを追加しました。v0.9.0ではライブハウス・ホール・アリーナと3段階の会場感を追加し、LIVEの反射・残響を専用モジュールで再設計しました。以下の表は v0.7.2 時点の差分です。STEM、専用修復、参考曲への自動調整、セッション保存の差は引き続き残ります。[音色・演出の実装](sound-color.md)、[会場LIVEの実装](live-venues.md)を参照してください。

現時点の Web は、完成済みのモノラル／ステレオ音源1本を解析し、適応補正・マスタリングして候補を提示する段階です。Desktop と機能同等ではありません。特に複数素材から曲を仕上げるミックス機能と、演出モードの幅に差があります。

追記 v0.11.0: STEM（2〜16素材）とボーカル＋伴奏の複数ファイル入力、役割・音量・含める設定、先頭同期・末尾無音補完、合算ピーク保護、既存バス仕上げへの接続を実装しました。上記および以下の表のv0.7.2比較は履歴です。素材ごとの適応補正、自動バランス／マスキング調整、拍の自動位置合わせ、保存・復元は引き続き課題です。[STEM入力の範囲](stem-input.md)。

Web の AUTO は、曲の測定に応じて処理を選ぶ基礎を持っています。ただし、完成済み音源のボーカル／ドラム等を個別トラックとして自由に調整する機能はありません。「全自動ミックスがDesktopと同等まで完成した」と表示すべきではありません。

Desktopの「ボーカル楽器（2mix）」は2ファイル入力を指します。Web文書の「ステレオ2mix」は完成済み1ファイルを指すため、説明で区別します。

## 次の実装単位案

### 1. LIVE・音声演出の選択を整える

- 最初はライブハウス／ホールと「控えめ・標準・はっきり」の意図で選ぶUI。
- Masteringの方向（AUTO / IMPACT）と音声演出の選択を独立した設定データとして扱う。既存LIVE入口との互換を維持する。
- 演出は1つだけ選択可能にし、原音復帰、候補生成、音量一致A/Bを用意。
- レトロ系は少数ずつ専用DSPモジュールとして追加し、UIからDSPを直接呼ばない。
- テスト: 会場・演出切替、取消、Original不変、有限値／ピーク／DC保護、音量一致比較、書き出し。

### 2. 複数素材の自動ミックスを追加する

- 最初はボーカル＋伴奏の2ファイルを対象に、素材ごとの解析 → MixPlan → 素材処理 → Bus解析 → Masteringと進める。
- 長さ・開始位置・サンプルレートの扱い、素材合計PCMの制限を先に定義する。
- 次にドラム／ベース等のSTEMへ拡張。完成済み1本からの音源分離は別機能であり、素材入力と混同しない。
- テスト: 同期・長さ・役割切替・バランス判断・合算ピーク・キャンセル・メモリ上限。既存単体音源ルートの回帰確認。

### 3. 修復・参考曲・保存・出力を小分けに追加する

- 専用修復を検出根拠と確信度付きで導入。元から存在する歪みを無条件に消せるとは表示しない。
- 参考曲の解析は、音量差を除いた帯域・ダイナミクス等を計画に反映。異なる曲への一致を品質保証にしない。
- セッション／候補履歴の保存、24bit WAV、完成音源レポートを順に実装。
- MP3等はコーデック・配布ライセンスとブラウザ互換を調査してから追加。

これらは優先順位案です。この確認では機能実装や既存Desktopの変更は行っていません。

## 移植時に維持する境界

- Original保護、別buffer候補、Worker処理、キャンセル、音量一致A/B、再解析・Quality Gateを維持する。
- 修復と意図的な演出の品質評価は区別する。演出のための帯域変化・ノイズを誤って修復対象にしない。有限値・ピーク・DC等の安全条件は共通に守る。
- OSデバイス設定、Tkinter、Windows配布・署名等はDesktopに残す。VST3ホストがこのZIPで実装済みとは今回の資料から確認できない。
- 音声演出はMusicSyncの対象。歌詞・Typography・映像・MV等はZUNZUNの範囲を維持する。
- Python／ネイティブ依存や素材をそのままWebへコピーしない。アルゴリズム・コーデック・IR・ライブラリの権利を確認し、重さを測定した後でWASM等の採用を判断する。
