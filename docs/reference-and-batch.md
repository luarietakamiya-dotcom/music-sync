# お手本に近づける仕上げとアルバムの一括仕上げ

Music Syncは音源を解析し、必要と判断した補正だけを選びます。参考曲の音色・低域・密度の傾向を利用できますが、演奏、楽器編成、ミックスそのものを複製する機能ではありません。測定上の接近と安全性を確認し、耳でOriginalと比較するための候補を作ります。

## Webでの使い方

1. 仕上げる曲、またはSTEMから作ったミックスを読み込みます。
2. 「参考曲」にお手本を追加し、使用する設定と適用量を選びます。読み込むだけでは現在のBを変更しません。
3. AUTO / IMPACT / LIVEと出力先を選び、仕上げます。参考曲の補正は通常の仕上げの後に評価されます。
4. Original / Processedをラウドネスマッチで聴き比べ、気に入れば保存します。

複数の完成曲は一括仕上げへ追加します。曲を順に仕上げて再測定した後、安全に到達できる共通の音量を決めます。各曲を確認して個別保存、またはZIPでまとめて保存できます。一括キューはSTEMミキサーではなく、完成曲を並べて処理する機能です。

## リファレンスの解析と処理

`analyzeReference(audio)`は`AnalysisResult`と`PerceptualFeatures`から、JSONとして保存できる`ReferenceProfile`を生成します。ストリーミング解析の結果には`profileFromMeasurements(analysis, features)`を使えます。

- 参考曲は24 kHz以上、2秒以上で、解析の確かさが0.5以上必要です。無音、クリッピング、単一音など比較情報が少ない素材は拒否します。ファイル形式の上限は後述の表を参照してください。
- sub + low、lowMid、mid、upperMid + presence、highを、低音・暖かさ・中域・存在感・高域の5グループにまとめます。各グループのエネルギー比を正規化して利用し、再生音量の大小で音色の基準を変えません。
- 比較帯域は0–10 kHzです。10 kHzからNyquistまでのair帯域を除外し、44.1 / 48 / 96 kHzなどで比較する帯域を共通にします。低レート音源から不足した高域を推測して生成する処理ではありません。
- 差が小さい帯域や、根拠が不足する帯域へ補正を強制しません。最大3つの広いEQを選択し、各±1.5 dB、絶対値の合計4 dB以内に制限します。
- 密度の調整は、元の強弱、帯域ごとの音量変動、ピークの余裕がある場合のみです。追加圧縮は最大0.8 dBで、既存処理の圧縮予算も考慮します。音量を上げるだけで「似た音」と判定しません。
- 参考曲のLUFSを出力目標へコピーしません。選択した出力先と、通常の仕上げで安全に達成した音量を維持する方向で処理します。

`planReferenceCorrection`が処理計画を作り、DSPの`createReferenceProcessor`がその計画を実行します。フィルターとステレオ連動ダイナミクスの状態はチャンク間で持続します。Coreの計画にモード固有のDSPコードを埋め込みません。

補正は同じ候補から最大3回、通常量・半分・4分の1の順に試します。毎回再解析し、お手本との帯域・強弱の距離が改善したか、クリッピング、推定True Peak、LUFS / RMS、Crest Factor、DC Offset、ステレオの安定性、低域の偏り、高域の刺さりなどを確認します。さらにOriginalからの変化を既存の品質判定で確認します。

結果は`accepted`、`skipped`、`rejected`です。不要な処理は`skipped`、改善または安全性を確認できない補正は`rejected`になり、先に仕上がったBを保ちます。`rejected`を「お手本に一致した」と表示しません。距離の改善は聴感やプロ品質の保証ではありません。

## 一括仕上げの音量合わせ

最初に曲ごとの仕上げを行い、採用された候補の実測値から`planBatchLoudness`で共通の音量を計画します。標準の希望値は-16 LUFSです。共通目標は、各曲の安全なピーク余裕、最大+3 LUの持ち上げ量、希望値のうち最も控えめな値を超えません。

その後の音量合わせは全曲のゲインだけを変えます。この工程で追加CompressionやLimiterを使いません。強弱をつぶして希望値へ無理に合わせる代わりに、アルバム全体を低めの音量にすることがあります。無音や不正な測定、クリッピングのある曲などは理由を表示して対象から外します。

保存した音声を再解析し、計画した音量変化、ピーク、長さ、Crest Factor、DC Offset、ステレオの値を確認します。共通LUFSは聴感の目安であり、アレンジや音色による大きさの違いまで等しくする保証はありません。

## ファイル、保存、処理範囲

| 項目 | 現在の範囲 |
| --- | --- |
| 一括キュー | 最大20曲、入力ファイル合計2 GiB |
| 一時出力 | 合計4 GiBまで。ブラウザの利用可能な保存容量が少ない場合は先に制限されます |
| ZIP | 最大2 GiB。残っている一時保存容量によって、さらに小さい上限になる場合があります |
| WAV入力 | 1ファイル512 MiB・20分、モノラル / ステレオ、PCMまたはFloat32。Float32への展開後出力も512 MiB以内 |
| FLAC入力 | 1ファイル100 MiB、展開後96 MiB以内。ブラウザのデコード対応も必要です |
| 短尺処理 | 10分・展開後96 MiB以内など、通常のCore処理の制限内でAUTO / 色付け / 調整を利用 |
| 長尺処理 | ファイルをチャンク処理。参考曲の補正もチャンク間の状態を保持しながら別の一時ファイルで評価 |
| 長尺の音色プリセット | 未対応。選択されている場合は対応外と説明し、黙って別の音へ置き換えません |

重い解析とDSPはWorkerへ渡し、一括処理は曲ごとに順次実行します。長尺の参考曲補正は一時候補へ書き出して品質を確認し、採用時だけ処理中のB用保存先へ反映します。Originalを上書きしません。キャンセル、失敗、対象外の曲は完了と区別して表示します。

素材と音声処理はブラウザ内で完結し、有料APIや音声アップロードを必要としません。一時音声はブラウザのローカル領域に置きます。

既存のWAV Float32 / 24-bit / 16-bit、MP3と曲情報・ジャケット登録を利用できます。一括の個別保存とZIPは選んだ保存形式を使用します。MP3の曲名を空欄にすると元のファイル名を基にします。WAVは元のサンプルレートを保ち、16-bitの選択だけでCD用形式へ変換しません。MP3は入力に応じて対応する出力サンプルレートへ変換される場合があります。

通常のプロジェクトには、参考曲のファイルと有効 / 無効・適用量も保存します。復元時には参考曲を再解析してから設定を反映します。一括キューとその途中結果はプロジェクト保存の対象ではありません。再開が必要な一括結果はダウンロードして保持してください。

## Coreをアプリへ組み込む

ソースツリーの `examples/reference-and-batch.mjs` は外部ファイルやサービスを使わず、24 kHz・4秒の合成音を生成します。

```sh
npm install
npm run build
node examples/reference-and-batch.mjs
```

主なAPIは以下です。

```js
const profile = analyzeReference(referenceAudio);
const finished = autoMixMaster(sourceAudio, 'AUTO', {
  reference: { profile, strength: 0.65 },
});

// 採用された候補がある場合だけ、次の計画へ進みます。
if (finished.status === 'accepted' && finished.processed && finished.finalAfter) {
  const plan = planBatchLoudness([
    { id: 'track-1', analysis: finished.finalAfter },
  ], { targetLufs: -16 });
  console.log(plan.commonTargetLufs, plan.tracks);
}
```

呼び出し元は`finished.status`と`processed`の有無、各曲の計画の`status`を確認してください。CoreはDOM、OPFSやダウンロード操作を要求しません。独自ホストでは計画のゲインをコピーへ適用し、書き出した音声を再解析して確認してください。

## 今後の編集機能

DAWのようなタイムラインでの分割、ミュート、挿入、つなぎ合わせは今後の候補です。現時点では実装していません。追加する場合は素材を不変で保持し、クリップが参照する素材内の範囲とタイムライン上の位置を分離します。Undo可能な編集履歴、境界のクロスフェード、書き出し後の品質確認を含む別の段階として設計します。
